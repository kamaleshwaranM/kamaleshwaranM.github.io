Projects

Two products on SAP BTP Cloud Foundry, built in one monorepo with shared CI/CD. Select a card to open the details.

Employee and kiosk time tracking: Expo/React Native app, Express API, OAuth broker and cron worker.

Node.jsMongoDBReact NativeOAuth
  • Offline-first punches. Every clock action is saved on the device before any network call, so the UI always reflects local truth.
  • Safe on shared kiosks. Each user has their own queue, and shared devices use a separate one, so punches can't mix between users.
  • Duplicate-safe delivery to SuccessFactors. Idempotency keys, plus separate tracking for device→API and API→SuccessFactors.
  • Stateless OAuth broker. The mobile app never holds the client secret. Rate limiting, schema validation and a tenant allowlist protect the auth surface.
  • Automatic data retention. Partial TTL indexes let MongoDB expire old logs itself (13 months for punch and report logs, 3 months for app logs).
  • Report pipeline. CSV, password-protected ZIP, S3, then SMTP, with each stage isolated so a mail failure can't lose the file.
  • Device features. GPS geofencing, biometric confirmation, English/Spanish, per-tenant feature flags, and one codebase shipping as three store builds (dev, test, prod).

Overtime ingest, approval workflow and payroll write-back through SuccessFactors.

TypeScriptMongoDBOData v2React / UI5
  • Sync you can trust. Per-tenant locks and watermark-based delta sync. The watermark only advances after a successful run.
  • Ingest quarantine. Records that can't be placed are stored with reason codes and retried with exponential backoff from 15 minutes up to 6 hours.
  • Idempotent payroll write-back. Approved hours are sent to SuccessFactors over OData $batch, with a clear sync-status state machine.
  • Immutable audit trail. Approvals and audit records freeze their state at creation. CSV export is bounded to 31 days and 1,000 rows.
  • Secure viewer. The SAP approuter requires login on every route with CSRF protection. Roles come from SuccessFactors relationships, so the app has no separate permission system.
  • Tenant by hostname. The tenant is resolved from the request host and themed per customer.
